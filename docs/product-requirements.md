# 产品要求与实现边界

任务基准日期为 2026-10-16（北京时间）。目标用户为愿意明确授权项目、在电脑检查结果的个人开发者。眼镜提供简短状态和采集入口；手机负责中文字体、语音服务、联网和持久媒体；电脑负责智能体执行。

## 三种载体必须区分

**H1** 是优先研发的整机架构和供应商询价规格。左眼单目透明 HUD；右镜腿前端放摄像头与计算模块，减少 DVP 经过活动铰链。两侧镜腿分配受保护电池。处方片应由验光机构加工，独立于光机出瞳。

**D0** 是已有可编译固件对应的有线开发台架。使用可采购开发板、DVP 摄像头、ST7789 LCD、I2S 麦克风/功放、SD 和测试联锁。D0 不以日常佩戴、透明显示或轻量作为已实现指标。不能把 D0 的编译记录用于证明 H1 驱动或光学已完成。

**Halo HUD 适配** 是现成近眼平台的独立实验入口。只镜像状态，不承诺解决 H1 离线录像、存储、结构制造问题，也不把 Halo 的厂商重量或电池宣传移植为本项目实测。

## 模式

| 模式 | 目标 | 已有实现 |
|---|---|---|
| A 独立 | 本地时钟、按键拍照、缓存、简单菜单 | D0 有校时后时钟与物理短按拍照代码；断电后时间显示未知；菜单和离线语音命令未完成 |
| B 手机协同 | 中文输入/转写、AI 文字、手机语音、照片与短录制保存、通知 | Android 原生实现并构建；眼镜音频上传后可显式请求云转写；手机运行与 BLE 待实测 |
| C 智能体 | 用户确认目标项目后启动、追踪、继续、取消 Codex | HTTPS/SQLite/协议测试与模拟通过；真实容器与模型执行待验收 |

H1 先做间歇信息 HUD，不做全视野沉浸、SLAM、导航安全保证或替代手机屏幕。单目减少一套面板、光学和标定负担；代价是左右眼视觉差异、部分人不适、右/左眼优势及出瞳对准必须试戴验证。若使用者无法适应左眼显示，应调整产品版本，不能仅旋转一张图当作完成适配。

## 量化目标

50g 与 8h 是挑战目标，不是交付承诺。当前包含处方片、电池保护、FPC、铰链/螺钉、音腔及装配余量的质量预算约 66g。8h 只针对 `hardware/power/budget.json` 的混合负载；连续显示、连续语音、连续录制分别单列，见可计算模型。接触表面设计目标为 40°C 以下，属于内部项目目标，不是引用标准中的通用法定温度限值。

H1 HUD 目标 640×480、约20°对角 FOV、18mm eye relief、8×6mm eyebox、至少70%环境透过率。只有面板规格有供应商资料；FOV 是近轴估算，其他为待询价/实测的验收门槛。D0 现有 HUD 是 128×64 单色位图显示于 240×240 台架 LCD，不可偷换为 H1 规格。

拍照当前固件配置为 800×600 JPEG；录制是 320×240、目标5fps、最长15秒的带时间戳 JPEG 帧容器，不是 H.264/4K 视频。I2S 录音为16kHz PCM16单声道 WAV、每段最长8秒。H1 升级2MP、双麦及高效编码要重新验证器件和内存带宽。手机 TTS 输出和眼镜端最长8秒缓存语音播放代码已实现；真实扬声器输出、音质及等待时间仍待实测，不能称为已验证的低延迟会话。
